SEED 디자인 시스템 분석

당근 SEED의 토큰 아키텍처를 브라우저에서 실측한 564개 CSS 변수로 살펴봅니다.

Design System Analysis 2026. 8. 1. · 5분 읽기
$dimension.x4 $color.fg.brand $spacing-x.global-gutter

왜 토큰인가

디자인 토큰은 디자인 결정을 사람과 기계가 모두 이해할 수 있는 방식으로 인코딩하는 방법입니다. SEED는 이를 "값이 아니라 의미로 관리한다"는 원칙으로 구현합니다. 같은 #f60이라도 브랜드 배경(bg.brand.solid)과 브랜드 텍스트(fg.brand)는 별도 토큰입니다. 의미가 다르면 따로 업데이트할 수 있어야 하기 때문입니다.

2계층 구조

SEED 토큰은 Scale Token(raw 값에 이름 부여)과 Semantic Token(Scale을 조합해 의도 표현)의 2단계로 계층화되어 있습니다. 실측 결과 웹 런타임에는 총 564개의 --seed-* 변수가 노출됩니다.

Semantic Token $spacing-x.between-chips $color.fg.brand $spacing-x.global-gutter
Scale Token $dimension.x2 $color.palette.carrot-600 $dimension.x4
Raw Values 8px #FF6600 16px

역할 기반 색상

색상은 bg(43개) / fg(16개) / stroke(16개)의 세 역할과, 예외 상황을 위한 팔레트 색상(94개, 각 색 100~1000 스케일)으로 구성됩니다. 모든 역할 기반 색상은 WCAG가 아닌 APCA 명도 대비 기준을 충족하도록 설계된 점이 차별점입니다.

유동 타이포그래피

14단계 스케일(t1~t14)의 각 사이즈는 고정값이 아니라 clamp(11px×0.8, 0.6875rem, 11px×1.5) 같은 유동형입니다. 사용자의 폰트 배율 설정에 0.8~1.5배 범위로 반응하며, 고정이 필요하면 -static 변형을 씁니다. 접근성이 스케일 설계 단계부터 들어가 있는 셈입니다.

배운 점

이 포트폴리오 사이트 자체가 SEED에서 실측한 토큰으로 만들어졌습니다. 범용 시스템 위에 서비스 고유 토큰(매너온도 등)을 얹는 확장 패턴, pressed 상태까지 토큰화하는 꼼꼼함, 모션 duration 6단계 등 작은 결정들이 쌓여 일관성을 만든다는 것을 확인했습니다.
