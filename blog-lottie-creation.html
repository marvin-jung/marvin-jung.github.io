Lottie 직접 만들기 — 도구별 가이드

지난 글에서 Lottie를 웹에 넣는 법을 다뤘습니다. 이번엔 그 앞 단계 — 애니메이션 자체를 만드는 다섯 가지 경로를 예산·숙련도별로 정리합니다.

Tutorial Lottie Tools 2026. 8. 1. · 7분 읽기

다섯 가지 경로, 한눈에

Lottie 제작은 결국 "keyframe이 담긴 JSON을 어떻게 얻는가"의 문제입니다. 도구·예산·목적에 따라 경로가 갈립니다:

경로도구비용적합한 경우
A. 정석After Effects + BodymovinAE 구독 (플러그인은 무료)복잡한 모션, 프로 워크플로
B. 브라우저LottieFiles Lottie Creator무료 플랜 있음AE 없이 처음부터 제작
C. 피그마LottieFiles for Figma무료 플랜 있음이미 Figma로 디자인할 때
D. 리컬러무료 에셋 + 색 교체무료가장 빠른 결과물
E. 손코딩텍스트 에디터무료단순 도형, 개발자

경로 A — After Effects + Bodymovin (정석)

업계 표준 파이프라인입니다. AE에서 셰이프 레이어 중심으로 애니메이션을 만들고, 무료 확장 Bodymovin(aescripts에서 name-your-own-price로 배포, ZXP Installer로 설치)으로 컴포지션을 JSON으로 내보냅니다.

절차는 네 단계입니다: ① aescripts에서 Bodymovin 다운로드 → ZXP Installer로 설치 → AE 재시작 ② AE 환경설정에서 "스크립트가 파일에 쓰기 허용" 체크 ③ Window → Extensions → Bodymovin에서 내보낼 컴포지션 선택 ④ Render 버튼 → .json 출력. 핵심 제약: 모든 기능이 지원되진 않습니다. 셰이프·트랜스폼·마스크·트림패스는 안전하지만, 일부 이펙트·3D·표현식은 렌더러별로 미지원이라 airbnb/lottie 저장소의 supported features 문서를 기준으로 설계해야 합니다. 래스터 이미지를 쓰면 JSON에 base64로 박혀 파일이 급증하니 벡터로만 구성하는 것이 정석입니다. → 상세 튜토리얼 ①편

경로 B — LottieFiles Lottie Creator (브라우저)

AE가 없다면 LottieFiles의 Lottie Creator가 가장 접근성 좋은 대안입니다. 브라우저에서 도형을 그리고 타임라인에 keyframe을 찍어 바로 Lottie로 내보냅니다. 무료 플랜으로 시작할 수 있고, 결과물을 dotLottie(.lottie — JSON을 압축한 포맷)로도 받을 수 있습니다. 전문 모션 툴 대비 기능은 단순하지만, 이 블로그 히어로 수준의 도형 애니메이션은 충분히 커버합니다. 유사한 웹 도구로 Jitter(jitter.video)도 Lottie 내보내기를 지원합니다. → 상세 튜토리얼 ②편

경로 C — Figma에서 바로 만들기

이미 Figma로 디자인한다면 LottieFiles for Figma 플러그인이 지름길입니다. Figma 프레임 간 전환을 애니메이션으로 만들어 Lottie로 직접 내보내는 방식이라, 정적 시안을 그대로 살릴 수 있습니다. 2026년 7월 업데이트로 플러그인에서 Lottie 직접 내보내기가 강화됐습니다. 제약도 명확합니다: Figma의 표현 범위(프레임 전환 기반)를 넘는 정밀한 타임라인 제어는 어려우므로, 복잡한 모션은 경로 A/B로 가는 것이 맞습니다. → 상세 튜토리얼 ③편

경로 D — 무료 에셋을 내 브랜드로 (최속)

결과물이 급하다면 만들지 말고 고르세요. LottieFiles 라이브러리에는 무료 에셋이 방대하고, 에디터에서 색상만 브랜드 토큰으로 교체하면 몇 분 만에 "우리 것"이 됩니다. 이 포트폴리오라면 오렌지 #FF6600과 그린 #079171로 바꾸는 식입니다. 색은 JSON 안에 0~1 정규화된 RGB 배열로 저장되므로("c":{"k":[1,0.4,0,1]} = #FF6600) 텍스트 치환으로도 가능합니다. 라이선스만 확인하세요 — 무료 에셋은 대부분 Lottie Simple License지만 표기 조건이 있는 경우가 있습니다.

경로 E — JSON 손코딩 (개발자의 길)

단순한 도형 애니메이션이라면 에디터 없이 JSON을 직접 쓸 수 있습니다. 이 블로그 메인의 히어로 애니메이션(맥박 치는 씨앗 + 리플 + 궤도 점)이 정확히 이 방식으로, 레이어 3개짜리 JSON을 손으로 작성한 것입니다. 뼈대 구조와 keyframe 문법은 이전 글의 데모 섹션에 실제 코드와 함께 정리되어 있습니다. 규칙 몇 개만 기억하면 됩니다:

// 최상위: fr(fps), ip/op(시작/끝 프레임), w/h(캔버스), layers[]
// 레이어: ty:4(도형), ks(트랜스폼: o불투명도 r회전 p위치 a앵커 s스케일)
// keyframe: {"a":1, "k":[{ "t":프레임, "s":[값], "o"/"i":이징 베지어 }]}
// 도형: el(타원) rc(사각형) sh(패스) + fl(채움) st(선) + tr(그룹 트랜스폼)
// 색: 0~1 정규화 RGBA — #FF6600 → [1, 0.4, 0, 1]

공통 최적화 체크리스트

어느 경로로 만들든 내보내기 전에 이것만 점검하세요. 벡터 유지(래스터 이미지 임베드 금지 — 파일이 KB에서 MB로 뜁니다), 루프 설계(첫 프레임과 끝 프레임의 상태를 일치시켜야 이음새가 안 보입니다), 레이어 수 절제(모바일 성능), 포스터 이미지 준비(로딩 전 표시용 정지 이미지 — SEED가 WebP 포스터를 쓰는 이유), 그리고 재생/정지 컨트롤과 prefers-reduced-motion 대응(접근성 — 구현 코드는 이전 글 참조).

마무리

정리하면: 프로 품질이 필요하면 A(AE+Bodymovin), 도구 없이 시작하려면 B(Lottie Creator), Figma 사용자라면 C, 오늘 당장 필요하면 D(에셋 리컬러), 단순 도형이고 코드가 편하면 E(손코딩)입니다. 어느 길이든 결과는 같은 JSON이고, 웹에 얹는 방법은 이전 글 그대로입니다.
