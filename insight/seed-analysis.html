SEED 디자인 시스템 해부 — 토큰에서 지렁이까지

당근 SEED를 문서로 읽지 않고 직접 해부했습니다. 런타임 CSS 변수 564개, 랜딩의 픽셀 수치, 번들 JS 속 모션 구현까지 — 그리고 그걸 그대로 재구현하며 밟은 함정들의 기록.

Design System Analysis Reverse Engineering 2026. 8. 1. · 20분 읽기
$dimension.x4 $color.fg.brand $spacing-x.global-gutter

이 글의 방법론

이 글의 모든 수치는 세 가지 방법으로 직접 얻었습니다. ① 런타임 실측 — 브라우저에서 getComputedStyle과 스타일시트 순회로 CSS 변수를 전수 추출하고, 요소들의 크기·색·위치를 getBoundingClientRect로 측정했습니다. ② 바이너리 검사 — 이미지 파일의 청크를 직접 읽어 정지/애니메이션 여부를 판별했습니다. ③ 번들 코드 추적 — 난독화된 프로덕션 JS에서 컴포넌트 구현부를 검색해 애니메이션 파라미터를 읽어냈습니다. 문서에 없는 것까지 포함해, 아래 내용은 전부 그 결과입니다. 그리고 이 사이트 자체가 그 실측값으로 지어졌기 때문에, 재구현 과정에서 밟은 함정들도 함께 기록합니다.

토큰 아키텍처

2계층 구조 — 값이 아니라 의미

웹 런타임에는 총 564개의 --seed-* CSS 변수가 노출됩니다. 구조는 명시적인 2단계입니다. Scale Token은 무한한 raw 값 중 쓸 값을 제한하고 이름을 붙이며($dimension.x4 = 16px), Semantic Token은 Scale을 조합해 의도를 표현합니다($spacing-x.global-gutter → x4). 같은 #FF6600이라도 브랜드 배경과 브랜드 텍스트는 별도 토큰입니다 — 의미가 다르면 따로 업데이트할 수 있어야 하기 때문입니다.

Semantic Token $spacing-x.between-chips $color.fg.brand $spacing-x.global-gutter
Scale Token $dimension.x2 $color.palette.carrot-600 $dimension.x4
Raw Values 8px #FF6600 16px

역할 기반 색상 — bg / fg / stroke

색상은 세 역할로 나뉩니다: bg(배경, 43개), fg(전경, 16개), stroke(테두리, 16개). 각 역할은 의미 카테고리(brand, neutral, critical, informative, positive, warning, magic, disabled, layer)와 강도 변형(solid/weak, -pressed, -contrast, -muted, -subtle)의 조합입니다. 눌림 상태까지 토큰인 것이 인상적입니다.

color-bg-brand-solid#f60당근 브랜드 오렌지
color-bg-brand-solid-pressed#e14d00브랜드 버튼 눌림

팔레트와 서비스 특화 토큰

역할로 표현하기 어려운 예외를 위한 팔레트 색상 94개(각 색 100~1000 명도 스케일, carrot-100 #fff2ec → carrot-1000 #471601)가 별도로 있고, 그 위에 매너온도용 color-manner-* 20개, 배너 파스텔 10개 같은 서비스 고유 토큰이 얹힙니다. 범용 시스템 위에 도메인 토큰을 확장하는 패턴입니다. 접근성 기준은 WCAG가 아닌 APCA 명도 대비를 채택했습니다.

타이포그래피와 나머지 스케일

14단계 타이포 스케일(t1~t14)의 각 사이즈는 clamp() 유동형입니다:

--seed-font-size-t1: clamp(calc(11px * .8), calc(.6875rem * 1), calc(11px * 1.5));
--seed-font-size-t1-static: 11px; /* 고정이 필요할 때 */

사용자 폰트 배율에 0.8~1.5배로 반응합니다 — 접근성이 스케일 설계 단계부터 들어가 있습니다.

랜딩 페이지의 해부학

캔버스와 스케일

랜딩은 히어로 아래 전체가 #121212 단일 다크 캔버스입니다. 섹션 제목은 데스크톱 52px, 모바일 28px의 화이트 볼드. 콘텐츠는 와이드하게 흐릅니다 — 원칙 카드 폭 640px, 기반(쇼케이스) 카드 430×242px(뷰포트 1800px 기준 실측). 처음 재구현 때 라이트 배경 + 26px 제목 + 960px 컨테이너로 만들었더니 구조는 같은데 완전히 다른 사이트처럼 보였습니다. 구조보다 스케일과 톤이 인상을 지배합니다.

내비게이션 — 떠 있는 필

fixed 플로팅 필(pill): 상단 20px, 중앙 정렬, 아이템 16px/400, 패딩 6×12px, 아이템 간 갭 2px. 전 항목이 페이지 링크입니다 — 앵커와 페이지 링크를 섞으면 정보 구조가 바로 지저분해진다는 걸 제 사이트에서 확인했습니다.

인트로와 거대 마크

"당근의 디자인 시스템 SEED" 섹션: 좌측 제목 52px/700/화이트, 우측 설명 22px, 줄 단위 마스크 구조. 그 아래 거대 로고 마크의 정체는 이미지가 아니라 1785×900 풀블리드 Lottie SVG였습니다. 재구현하며 배운 기하학 하나 — preserveAspectRatio: slice 크롭에서는 화면이 넓을수록 보이는 세로 영역이 좁아지므로(보이는 comp 높이 = 컨테이너높이 ÷ 가로배율), 컨테이너 높이를 vw 비례로 두면 보이는 영역이 상수가 되어 어떤 폭에서도 잘리지 않습니다.

모션 시스템 — 번들 코드 추적

움직이는 이미지의 정체: Lottie + 정지 포스터

랜딩의 살아있는 그래픽은 <video>도 GIF도 아닙니다. 페이지의 WebP들을 바이너리로 검사하니 전부 ANIM 청크가 없는 2~20KB 정지 이미지 — 로딩 전 포스터였고, 실제 모션은 window.lottie로 로드되는 Lottie JSON 4개(intro-parallax, bento tab/pin/seed)가 SVG 렌더러로 재생하는 것이었습니다. 우하단 "동영상 재생/일시정지" 버튼을 눌러도 video 요소는 끝내 생기지 않습니다 — Lottie 재생을 전역으로 켜고 끄는 접근성 컨트롤입니다.

텍스트 리빌 — 단어 마스크의 스펙

제목·설명이 차오르는 효과의 구현부를 번들 JS에서 추적했습니다. 텍스트 컴포넌트는 문자열을 split("\n")으로 줄을 나눈 뒤 split(" ")으로 단어 단위까지 분해하고, 각 단어를 inline-block overflow-hidden 마스크와 will-change-transform 스팬으로 감쌉니다. 애니메이션 설정 객체에서 읽어낸 값:

실측 파라미터

ease: "power3.out"   // GSAP (전역 gsapVersions: 3.15.0)
duration: 0.7
scrollTrigger.start: "top bottom"  // 요소 상단이 뷰포트 하단에 닿는 순간
// + rearm/onLeaveBack: 위로 벗어나면 리셋 → 재진입 시 다시 재생

핵심은 마지막 줄입니다. 한 번 보여주고 끝이 아니라, 스크롤을 되돌리면 리셋되고 다시 내려오면 재생됩니다. 살아있다는 감각은 이 재무장(rearm)에서 나옵니다.

'더보기'는 버튼이 아니라 커서다

기반 섹션 카드에 마우스를 올리면 나타나는 '더보기'를 DOM에서 아무리 찾아도 없었습니다. 번들 코드의 답: 카드에 data-cursor="text", data-cursor-text="더보기", data-cursor-arrow="right" 속성이 붙어 있고, 전역 커스텀 커서 시스템이 이를 읽어 커서 자체를 필로 바꿉니다. 카드 목록은 data-carousel-copy="original/duplicate"로 원본+복제 2벌을 이어붙인 무한 캐러셀이고, 카드 폭은 모바일 250px → 데스크톱 430px입니다.

접근성 정책 — 모션의 기본값

OS의 '동작 줄이기'가 켜진 기기에서 SEED를 관측하면 마퀴·자동재생·리빌이 전부 정지해 있습니다. 처음엔 측정 오류인 줄 알았는데, 의도된 정책이었습니다. 모션은 장식이 아니라 기본값을 가진 설정이고, 그 기본값은 사용자의 OS가 정합니다. 이 사이트도 같은 정책을 따릅니다.

문서 시스템의 디테일

문서 타이포 실측

문서 페이지(디자인 토큰, 패턴 등)는 랜딩과 완전히 다른 라이트 세계입니다: h1 60px/500, h2 24px/500, 본문 16px/행간 28px, 헤더 76px, 사이드바 링크 16px. 랜딩은 굵고 크게, 문서는 가늘고 밀도 있게 — 한 시스템 안의 두 보이스입니다.

목차의 지렁이 — clip-path 두 겹

문서 목차의 시그니처: 스크롤하면 검은 선이 지렁이처럼 늘었다 줄며 따라옵니다. 구현은 우아합니다 — 동일한 경로의 SVG 두 겹. 아래층은 연한 레일(경로가 h2/h3 레벨에 따라 x=8↔16으로 꺾이고, 링크 들여쓰기도 20px/32px), 위층은 진한 선인데 clip-path: inset(위 0 아래)를 스크롤마다 갱신해 활성 구간만 보입니다. 위·아래 가장자리가 서로 다른 속도로 움직여서 신축이 생깁니다.

재구현 노트

이 페이지 오른쪽 목차가 같은 원리의 재구현입니다: 이동 방향 쪽 가장자리는 빠르게(계수 0.22), 반대쪽은 느리게(0.09) 보간합니다. 함정이 하나 있었는데 — 활성 판정을 "뷰포트 20~30% 지점 통과"로 하면 문서 끝 섹션들은 물리적으로 그 지점에 도달할 수 없어서(페이지 바닥에 막힘) 지렁이가 끝까지 내려가지 못합니다. 페이지 바닥 도달 시 마지막 항목을 강제 활성하는 예외가 필요합니다.

재구현하며 밟은 함정들

분석은 반이고, 나머지 반은 재구현이 가르쳐 줬습니다. 전부 "눈으로는 멀쩡했고, 측정하니 아니었던" 것들입니다.

Lottie: easing 없는 keyframe은 레이어를 통째로 죽인다

손으로 쓴 Lottie JSON에서 마지막이 아닌 keyframe에 easing(o/i)을 빠뜨리면, 그 속성만 이상해지는 게 아니라 레이어 렌더 전체가 조용히 실패합니다(빈 화면, 에러 없음). 데모가 분홍 빈 박스로 나온 원인이 이것이었습니다.

스크롤 트리거의 세 가지 사각지대

① 빠른 스크롤은 콜백을 건너뛴다

IntersectionObserver는 요소가 프레임 사이에 뷰포트를 통째로 지나치면 콜백을 주지 않을 수 있습니다. 스크롤 스윕 폴백이 필요합니다.

② 경계에서의 플래핑

감시 로직이 둘이면(IO+스윕) 뷰포트 경계에서 서로 반대로 클래스를 붙였다 뗐다 하며 텍스트가 떨립니다. 단일 핸들러 + 히스테리시스(진입선과 리셋선을 분리)로 해결됩니다.

③ 로드 직후의 역방향 페이드

JS로 숨김 클래스를 붙이는 순간 보임→숨김 트랜지션이 한 번 재생되어 깜빡입니다. 첫 두 프레임은 트랜지션을 꺼 둬야 합니다.

블렌드 모드는 요소 단위로 계산된다

커서 필에 mix-blend-mode: difference를 쓰면 "배경에 따라 색이 변하는" 효과가 나긴 하는데, 밑에 있는 벡터 요소 하나하나와 개별 연산되어 필이 얼룩덜룩해집니다. 카드 단위 대표색을 읽어 전환하는 쪽이 의도에 가깝습니다.

종합 — 일관성은 작은 결정의 총합

SEED에서 가장 배울 만한 것은 화려한 무엇이 아니라, 작은 결정들이 전부 봉인되어 있다는 사실입니다. 눌림 상태의 색, 모션의 여섯 단계 duration, 리빌의 0.7초와 power3.out, 모션 감소 사용자를 위한 정지 기본값, 목차 선의 1.5px까지. 일관성은 선언이 아니라 이런 결정의 축적입니다. 이 사이트는 그 결정들을 실측해 세운 재구현이고, 이 글은 그 지도입니다 — 구조는 배우되, 얼굴(로고·일러스트·에셋)은 전부 새로 만들었습니다.
