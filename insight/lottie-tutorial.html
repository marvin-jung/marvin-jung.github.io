움직이는 이미지의 정체 — Lottie 튜토리얼

seed-design.io 랜딩의 살아 움직이는 그래픽은 동영상도 GIF도 아니었습니다. DOM을 해부해서 정체를 밝히고, 같은 것을 직접 만들어 봅니다.

Tutorial Lottie Motion 2026. 8. 1. · 10분 읽기

궁금증에서 시작

seed-design.io 첫 화면에는 부드럽게 움직이는 일러스트들이 있습니다. 흔히 떠올리는 후보는 넷입니다: <video>, GIF/애니메이션 WebP, CSS 애니메이션, 그리고 Lottie. 추측 대신 브라우저 콘솔에서 하나씩 배제해 봤습니다.

탐정 노트 — 하나씩 배제하기

1) 동영상? document.querySelectorAll('video') → 0개. 심지어 우하단의 "동영상 재생" 버튼을 눌러도 video 요소는 끝까지 생기지 않았습니다.

2) 움직이는 이미지 파일? WebP가 애니메이션인지는 파일 안에 ANIM 청크가 있는지로 판별할 수 있습니다:

// 콘솔에서: webp가 애니메이션인지 바이너리로 검사
const buf = await fetch('/landing/showcase/motion.webp').then(r => r.arrayBuffer());
const bytes = new Uint8Array(buf);
const hasAnim = bytes.some((_, i) =>
  bytes[i] === 65 && bytes[i+1] === 78 && bytes[i+2] === 73 && bytes[i+3] === 77); // "ANIM"
// 결과: false — 전부 2~20KB짜리 정지 이미지(포스터)였다

3) CSS 애니메이션? 스타일시트의 @keyframes를 전수 조사하니 스켈레톤 시머, 프로그레스 서클 같은 컴포넌트용뿐, 랜딩 그래픽용은 없었습니다.

정답 — Lottie

결정적 증거는 세 가지였습니다. 전역에 window.lottie 객체가 존재하고, 네트워크 리소스에 /landing/intro-parallax.json 등 애니메이션 JSON 4개가 로드되며, 움직이는 영역의 DOM이 <svg> + translate3d 인라인 스타일 + 98개의 그룹 — 전형적인 lottie-web SVG 렌더러 시그니처였습니다. 정지 WebP들은 Lottie 로딩 전에 깔리는 포스터였고, "동영상 재생/일시정지" 버튼은 Lottie 재생을 전역으로 켜고 끄는 접근성 컨트롤이었습니다.

Lottie 파이프라인

Lottie는 After Effects 애니메이션을 JSON으로 내보내(Bodymovin 플러그인) 웹/앱에서 벡터로 재생하는 포맷입니다. 파일이 수 KB로 작고, SVG라 어떤 해상도에서도 선명하며, 코드로 재생을 제어할 수 있습니다. AE가 없다면 LottieFiles의 무료 에셋·에디터를 쓰거나, 단순한 도형 애니메이션은 아래처럼 JSON을 손으로 쓸 수도 있습니다.

웹에 넣기 + 라이브 데모

<!-- 1. 라이브러리 (svg 전용 light 빌드가 가볍다) -->
<script src="https://cdnjs.cloudflare.com/ajax/libs/bodymovin/5.12.2/lottie_light.min.js"></script>

// 2. 로드 — 포스터 이미지를 배경으로 깔아두면 로딩 공백이 없다
const anim = lottie.loadAnimation({
  container: document.getElementById('hero-anim'),
  renderer: 'svg', loop: true, autoplay: true,
  path: 'my-animation.json'  // 또는 animationData: {...} 인라인
});

// 3. 제어
anim.pause(); anim.play(); anim.goToAndStop(frame); // 스크롤 연동은 진행률→frame 매핑

아래는 이 페이지에서 실제로 재생 중인 데모입니다 — 외부 JSON 없이 3개 레이어(맥박 치는 씨앗, 퍼지는 리플, 궤도 점)를 손으로 쓴 애니메이션 데이터입니다:

레이어 하나의 뼈대는 이렇게 생겼습니다 — ks가 트랜스폼(o=불투명도, r=회전, p=위치, s=스케일), shapes가 도형입니다:

{ "fr": 30, "ip": 0, "op": 90,  // 30fps, 0~90프레임(3초 루프)
  "layers": [{ "ty": 4,              // 도형 레이어
    "ks": { "s": { "a": 1, "k": [   // 스케일 keyframe: 88% → 106% → 88%
      { "t": 0,  "s": [88,88,100] },
      { "t": 45, "s": [106,106,100] },
      { "t": 90, "s": [88,88,100] } ] } },
    "shapes": [{ "ty": "el" }, { "ty": "fl", "c": {"k":[1,.4,0,1]} }] // 원 + 주황 채움
  }] }

접근성 — SEED가 가르쳐준 것

SEED의 플로팅 재생/정지 버튼은 장식이 아니라 움직임에 민감한 사용자를 위한 배려입니다. 두 가지를 함께 구현해야 완성입니다:

// OS의 '모션 감소' 설정을 존중 — 켜져 있으면 정지 상태로 시작
const reduced = matchMedia('(prefers-reduced-motion: reduce)').matches;
lottie.loadAnimation({ ..., autoplay: !reduced });

// 전역 토글 버튼 — aria-label도 상태에 맞게 갱신
btn.onclick = () => { anim.isPaused ? anim.play() : anim.pause(); };

보너스 — 스크롤 등장 효과와 두 가지 함정

SEED 랜딩의 섹션 fade-up은 IntersectionObserver + CSS 트랜지션(실측값: .5s, translateY(1rem))이면 충분합니다. 다만 직접 만들며 실제로 밟은 함정 두 개를 공유합니다.

함정 1 — 빠른 스크롤은 콜백을 건너뛴다. 휠을 세게 굴려 요소를 한 번에 지나치면 IO 콜백이 생략되어 영영 안 나타날 수 있습니다. 스크롤 스윕 폴백을 두세요:

addEventListener('scroll', () => targets.forEach(el => {
  if (!el.classList.contains('in') && el.getBoundingClientRect().top < innerHeight)
    el.classList.add('in');
}), { passive: true });

함정 2 — 로드 직후 역방향 페이드. JS로 숨김 클래스를 붙이는 순간 보임→숨김 트랜지션이 한 번 재생되어 깜빡입니다. 첫 두 프레임은 트랜지션을 꺼 두면 해결됩니다:

/* CSS */ body:not(.motion-ready) .reveal { transition: none; }
/* JS  */ requestAnimationFrame(() => requestAnimationFrame(() =>
  document.body.classList.add('motion-ready')));

마무리

정리하면 SEED의 "움직이는 이미지"는 Lottie(SVG 렌더) + 정지 WebP 포스터 + 전역 재생 컨트롤 + GSAP 스크롤 연출의 조합입니다. 이 포트폴리오의 메인 히어로가 정확히 같은 방식으로 만들어져 있으니, 뷰소스로 전체 구현을 확인할 수 있습니다.
